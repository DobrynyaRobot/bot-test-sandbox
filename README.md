# Архитектурное ревью pull request

Бот проверяет, не добавил ли плагин App Core в рабочие зависимости. Плагин может использовать этот пакет для тестов через `devDependencies`. [Правило](docs/architecture-policy.md#frontend-app-core)

## Как выбрать способ проверки

При открытии или обновлении PR автоматически запускается AACT.

Для ручного запуска откройте [Actions → Architecture review](https://github.com/DobrynyaRobot/bot-test-sandbox/actions/workflows/architecture-review.yml). Нажмите **Run workflow**, выберите ветку `main`, введите номер открытого PR в поле `pr_number` и выберите `mode`.

| Режим | Что делает |
|---|---|
| `aact` (по умолчанию) | AACT 3.0.1 проверяет настроенное правило. |
| `agent` | Модель читает изменения в `package.json` и документ с правилом. |
| `hybrid` | Модель получает те же файлы и находки AACT. Отчёт показывает, кто нашёл каждую проблему. |

Ручной режим относится к одному запуску. Результат появится в **Checks** для проверенного коммита PR.

Для `agent` и `hybrid` добавьте ключ OpenAI API в **Settings → Secrets and variables → Actions → New repository secret** под именем `OPENAI_API_KEY`. Эти режимы отправляют в OpenAI сравниваемые `package.json` и документ с правилом. Гибрид также передаёт сведения о находках AACT. Расходы учитываются в проекте OpenAI API.

## Куда нажать

| Пример | Где смотреть |
|---|---|
| Плагин добавил `@backstage/core-app-api` в `dependencies`. | [Открыть замечание к PR № 2](https://github.com/DobrynyaRobot/bot-test-sandbox/pull/2#issuecomment-7077172576). Нажмите на имя файла, чтобы перейти к строке. Под ней есть исправление, ссылка на правило и ссылка на точный коммит. |
| Пакет добавили только в `devDependencies`. | [Посмотреть изменения в PR № 3](https://github.com/DobrynyaRobot/bot-test-sandbox/pull/3/files). [Открыть чистый результат в Checks](https://github.com/DobrynyaRobot/bot-test-sandbox/runs/137194635981). |
| Нарушение и исправление в одном PR. | [Нарушение](https://github.com/DobrynyaRobot/bot-test-sandbox/runs/137194022131) · [Частичный охват](https://github.com/DobrynyaRobot/bot-test-sandbox/runs/137194403622) · [Исправление подтверждено](https://github.com/DobrynyaRobot/bot-test-sandbox/pull/8#issuecomment-7078516041). |

В PR откройте **Checks → Архитектура**. Там виден результат для проверенного коммита и переход к запуску в Actions. Статусы отдельно показывают нарушение, чистый результат, частичную проверку, неприменимое правило и сбой. При неполной проверке отчёт подскажет, какой файл или раздел нужно проверить вручную.

Бот обновляет один комментарий. После исправления он указывает, какую зависимость перепроверил. Если проверка неполна, прежнее замечание отмечается как неподтверждённое. Для PR без замечаний достаточно Checks. Если считаете замечание ошибочным, [попросите сопровождающего проверить его](docs/architecture-policy.md#если-замечание-спорное).

Проверка состоит из [запроса](.github/workflows/architecture-review-request.yml) и [проверяющего запуска](.github/workflows/architecture-review.yml). В PR из форка запрос может ждать одобрения GitHub. Если есть конфликт с `main`, сначала устраните его. Чтобы повторить проверку текущего коммита, откройте его **Architecture review request** и выберите **Re-run jobs** при наличии права записи.

Чтобы попробовать на своём PR, добавьте `@backstage/core-app-api` в `dependencies` файла [plugins/demo/package.json](plugins/demo/package.json) и откройте PR в `main`. Бот укажет добавленную строку.

## Что сравниваем в проекте

В исследовании сравниваем три способа ревью одного и того же PR. Агент читает изменение и архитектурные решения. AACT проверяет запрограммированные правила. В третьем варианте агент получает ещё и результат AACT. Сравниваем замечания с разметкой по исходникам и документам. Считаем найденные нарушения, пропуски и ложные замечания. Повторы показывают, насколько устойчив ответ.

В песочнице все три режима проверяют прямые зависимости в изменённых `plugins/**/package.json` и `packages/**/package.json` по документу из базовой ревизии.
